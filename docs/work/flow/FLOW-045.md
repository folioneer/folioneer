# FLOW-045 — The docs still treat a domain decision as an ADR candidate

- Kind: quality
- Observed: the owner, 2026-10-18, refusing an ADR for TODO-032's synced portfolio settings: an ADR records a developer-side technical choice that is hard to remove (the language, the framework, a data representation), never a domain decision, which the spec carries. #346 says so in the `adr-writer` gate only. `spec-reviewer` still flags "ADR candidates" on spec rules (how TODO-032's question arose); `adr-reviewer`, the ADR line of `CLAUDE.md` and `docs/agentic-setup.md` do not say it. Several accepted ADRs read as domain decisions: ADR-002 (a holding replaces the asset account), ADR-014 (what the price typed by hand leaves out of a fetch), ADR-018 (management fees generated lazily), perhaps ADR-012 (latest write wins, its source kept).
- Proposal: the definition lives once, in the `adr-writer` gate; `spec-reviewer`, `adr-reviewer`, `CLAUDE.md` and `docs/agentic-setup.md` point to it, and `spec-reviewer` no longer proposes an ADR for a domain rule. Each accepted ADR is classified developer-side (kept) or domain: its decision moved into the spec as a rule naming the test that guards it, then the ADR withdrawn as ADR-022 withdrew the code-organisation ones. Done when the gate is stated once and pointed to, every ADR in `docs/adr/README.md` is either developer-side or withdrawn with its rule in a spec, and `adr-reviewer` passes on what remains.
- Costs: M — docs and agent prompts only. Protects: an ADR is never asked of the owner for a domain decision again; the specs hold every domain decision.
- Needs the owner: no — the classification follows the owner's definition; a doubtful ADR is listed in the PR body.
