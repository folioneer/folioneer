# TODO-083 — (backend) — What an agent adds or records shows in the window at once

From gh247 (owner, 2026-10-12), which this entry closes when it ships: an asset an agent added with `add_asset` was in `list_assets` and in the price dialog, and the assets table showed it only minutes later, after other actions.

Seen again by the owner on the installed 0.10.0 (2026-10-13), while an agent rebuilt an account's history — about 240 transactions and 10 new assets in one session: the global view did not follow an account that had changed until the owner left the page and came back; in the account's journal a new asset showed under its identifier (`ab45454-…`) where its name belongs; and going to the global view and back to the journal put both right, never the page as it stood.

Read on 2026-10-13, not run: the event bus keeps one event — it is a `watch` channel, and the forwarder to the window reads what the channel holds when it wakes (`core/event_bus/bus.rs`, `app.rs`). A tool call publishes twice with nothing between: the write's own event from the service (`AssetUpdated` for an asset, `TransactionUpdated` for a recording), then `AgentConnectionChanged` once the call is counted (`server.rs`, `connections.notify()` right after `tools.run`). When the forwarder has not run between the two, the window is told the second only. `docs/backend-rules.md` B45 says an action publishes exactly one event, for this reason. It explains all three sights. The journal names an asset from the list of assets the window holds and falls back on its identifier (`useAccountJournal.ts`, `asset?.name ?? tx.asset_id`): a transaction that arrives for an asset the window was never told of shows the identifier. A view reads again when it opens, which is why leaving and coming back puts it right. And two hundred and fifty calls in a row lose the race far more often than one. It holds for every write an agent makes, not for assets alone.

**User value:** What an agent adds or records shows in the window right away, as what the owner types does, so the owner checks it while the agent is still working.
**Done when:** a test makes a write through the agent connection — an asset, a transaction, a price — with a listener on what the window is told, and both the write's event and the session's change reach it, every time; the same is held for many calls that follow one another at once, an added asset then a transaction on it among them; in the window, the journal of an account names an asset an agent has just added, and the global view follows a recording, without leaving the page; B45 and the agent's spec (AGT-036) say what a tool call publishes.
